## Performance

> Manual old-vs-new benchmark of the `--columnar` engine over the set in [`columnar_wip/benchmark-networks.md`](columnar_wip/benchmark-networks.md). This is **not** the CI `perf-pr.yml` check, which only sees the default OO path since the new core is flag-gated.

Single-threaded (`MODE=release OPENMP=0`), `--seed 123`. Codelength in bits. **`instr` is instructions retired** (`/usr/bin/time -l`). `time` is `--timing-json`'s `timing.total_s`.
- `-N10` rows run once (deterministic; `instr` carries the comparison).
- `-N1` rows are the interleaved minimum of 3.
- Driver: [`columnar_wip/bench-sync.py`](columnar_wip/bench-sync.py) `--carry-oo`, writing [`columnar_wip/stack-owner-ab-results.tsv`](columnar_wip/stack-owner-ab-results.tsv), old and new on every row of the previous snapshot (#1378).
- Bit-identity: [`columnar_wip/bench-identity.py`](columnar_wip/bench-identity.py), every columnar row once per arm, comparing the codelength and the body of every `.tree` file the run writes.
- Outliers in seconds: [`columnar_wip/retime-outliers.py`](columnar_wip/retime-outliers.py), writing [`columnar_wip/stack-owner-retime.tsv`](columnar_wip/stack-owner-retime.tsv).
- Tables: [`columnar_wip/assemble-hier-gaps.py`](columnar_wip/assemble-hier-gaps.py) builds every table from the TSV that [`columnar_wip/tables-1042.py`](columnar_wip/tables-1042.py) `assembly` writes, including the OO cells. The REG table comes from `tables-1042.py reg`.

> **This PR gives the columnar stacked hierarchy its own value type (#1371).** `ColumnarStack` holds the levels and assignments that were two raw vectors inside `ColumnarTwoLevel`. Every edit keeps each level the aggregate of the level below, including `insertLevel` and `removeLevel`, which no search uses yet. Checkpoints over an undo journal make any sequence of edits tentative without copying, and they nest. The operators now go through those edits. One `gatedStep` replaces four snapshot variants, `scoreStack` prices any stack without installing it, and corrections read a stack view instead of the optimizer. It is the first step of the split by role Daniel picked for #1371; the finding is F77.
>
> What the snapshot shows:
> - **All 332 columnar configurations are bit-identical**, in codelength and in the body of every `.tree` file a run writes (`_states.tree` included). So are the 33 configurations of [the feature build](#the-feature-build): multilayer input under `--regularized`, and `--lossy`.
> - **Instructions: median −0.10%, 5th–95th percentile −1.19% to +0.05%.** Every row beyond ±1% is a run under 0.15G instructions. The largest increase on a big run is single-run noise: om4_N256_E50k `-2d -N10` read +0.66% in the sweep and −0.12% as the minimum of 10.
> - **Seconds summed: +0.06%, and the slow cells are noise.** The 20 rows more than 10% slower in the sweep, re-run alternating as the minimum of 5: instructions −0.49% to −0.01%, seconds −5.9% to +2.8%. The three slowest above 2 s, air30k `--non-redundant`, REG word_assoc `-d --regularized` and om4_N256_E50k `-2d -N10`, read +0.87%, −0.13% and +0.37% as the minimum of 10, with medians −1.47%, −0.63% and +0.04%.
>
> Columnar arms measured in one session, 2026-10-25. OO arms carried from #1378, which carried them from #1377, #1376, #1373 and #1369's session.
> - **Old:** a fresh build of the branch tip `cc9560af` (#1378), md5 `64f033ed29985cdbd96d90ea836e5c06`. It is byte-identical to #1378's new arm. Feature build: md5 `fe6c5918cb4cc916ae014cf55ff47d97`, also identical.
> - **New:** `d04ac472`, md5 `758547164ea18c4c3f375e3cb9000af4`. Feature build: md5 `a8c34eb95df5077daaf9f0a8f0b8bf6b`.
> - **Family rows** that repeat a `-C`, `-C -2` or `-C -N1` row take that row's run, so the two tables agree.
