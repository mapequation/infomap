## Performance

> Manual old-vs-new benchmark of the `--columnar` engine over the set in [`columnar_wip/benchmark-networks.md`](columnar_wip/benchmark-networks.md). This is **not** the CI `perf-pr.yml` check, which only sees the default OO path since the new core is flag-gated.

Single-threaded (`MODE=release OPENMP=0`), `--seed 123`. Codelength in bits. **`instr` is instructions retired** (`/usr/bin/time -l`). `time` is `--timing-json`'s `timing.total_s`.
- `-N10` rows run once (deterministic; `instr` carries the comparison).
- `-N1` rows are the interleaved minimum of 3.
- Driver: [`columnar_wip/bench-1042.py`](columnar_wip/bench-1042.py), writing [`columnar_wip/1042-ab-results.tsv`](columnar_wip/1042-ab-results.tsv). One session, old and new on every row, plus two per-feature arms (below).
- Tables: [`columnar_wip/assemble-hier-gaps.py`](columnar_wip/assemble-hier-gaps.py) builds every table it built before, from the TSV that [`columnar_wip/tables-1042.py`](columnar_wip/tables-1042.py) `assembly` writes. The two new tables come from `tables-1042.py` `attribution` and `reg`.

> **This PR fixes #1042: under recorded teleportation, the columnar search counted teleportation twice (F68).**
> - **The bug.** FlowCalculator stores each node's enter and exit flow with the node's own teleportation already included, the object-oriented convention. The columnar leaf input copied those totals into fields that must hold link crossings only, and the move loop then added each module's teleport term on top. So under `--regularized` and `--recorded-teleportation` every move and merge was decided on a biased objective. Reported codelengths were right throughout, because the scorer rebuilds module boundaries from the links.
> - **What changes.** Three parts, each measured on its own in [the attribution table](#the-fix-feature-by-feature):
>   1. **Leaf fix:** each leaf's own teleport rates are stripped once, when the leaf level is built. This one is conditional by nature: only when teleportation is recorded do the stored rates include it.
>   2. **Collapsed-winner comparison**, on every run: if the two-level winner holds at least 90% of the flow in one module, the regroup ladder's best non-collapsed candidate is leaf-tuned too, and the better of the two is kept. This happens only when that candidate starts within 5% of the winner. #1042 needs it: the ladder judges candidates at the granularity of the first-pass blocks, and only a collapsed partition is immune to their impurity.
>   3. **Stalled-aggregation stop**, on every run: an aggregation pass that improves the codelength by less than 1e-4 of it is the last one.
> - **Everywhere else:** on the 225 configurations without recorded teleportation, parts 2 and 3 save 3.2% in instructions summed (1.7% in seconds), and one configuration moves, by −0.0026% in bits.
> - **Measured on all rows, not gated.** A first version applied parts 2–3 and a fourth one, skipping the trajectory repair before the ladder, under recorded teleportation only. Measured across the whole benchmark set, parts 2 and 3 are neutral-to-better everywhere. The skip cost 35 configurations up to 2.97% in bits for 4.3% in seconds, so it is dropped.
>
> Measured in one session, 2026-10-14.
> - **Old:** a fresh build of the branch tip `4c3e5c7b` (#1161), md5 `1a1fb5a5013e5827687a30fbb701fd01`.
> - **New:** this PR at `edbd9e83`, md5 `ccc09e195323b7bfa946f0de317c9179`.
> - **Feature arms:** fixonly (the leaf fix alone, on the recorded-teleportation searches) and cmp (leaf fix plus comparison, on every row).
> - **Load:** another benchmark shared the machine (1-minute load 6–13), so seconds run high on both arms alike, and `instr` is the steadier axis. The arms are interleaved per row; `-N1` rows are the minimum of 3 reps spread across the batch.
> - **Family rows** that repeat a `-C`, `-C -2` or `-C -N1` row take that row's run, so the two tables agree.
> - **OO arms** are not rerun, since this PR changes nothing the OO engine computes. Their cells are carried as #1140's and #1136's snapshots had them.
> - **lazega rows** now read `networks/columnar-benchmark/lazega.meta`, byte-identical to the `networks/meta/lazega.meta` earlier snapshots named.

Every recorded-teleportation search, plus every other row where an arm changed the codelength, old

### Every benchmark network under recorded teleportation

New in this snapshot. Every non-family network of the benchmark set runs under `--regularized`, and
also under `--recorded-teleportation` when it is directed. air30k `-d --regularized` is the tables'
"air30k (reg.)". multilayer and malaria are left out, because `--regularized` on multilayer input needs
the regularized-multilayer feature build. Rows run `-N10` once and `-N1` as the interleaved minimum of 3.

- **Gains:**
  - web-NotreDame: −16.96% in bits with `--recorded-teleportation`, −2.94% with `--regularized`.
  - netscience: −3.08% (`-2`). word_assoc `--recorded-teleportation`: −0.96%. jazz: −0.09% to −1.87%.
  - wikispeedia `--recorded-teleportation`: −0.38% / −0.60%.
- **The accepted cost:** powergrid, polblogs and word_assoc `--regularized` end at one module before and
  after, at +15% to +248% in instructions. See "What the change moves".
- **Worse in bits:**
  - wikispeedia `--regularized`: +0.08% / +0.15%. OO's 4.2865 bits sits below both arms.
  - lazega `--regularized`: +0.16% (−0.31% with `-2`).
  - The `-N1` single trials are listed above.
