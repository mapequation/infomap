## Performance

> Manual old-vs-new benchmark of the `--columnar` engine over the set in [`columnar_wip/benchmark-networks.md`](columnar_wip/benchmark-networks.md). This is **not** the CI `perf-pr.yml` check, which only sees the default OO path since the new core is flag-gated.

Single-threaded (`MODE=release OPENMP=0`), `--seed 123`. Codelength in bits. **`instr` is instructions retired** (`/usr/bin/time -l`). `time` is `--timing-json`'s `timing.total_s`.
- `-N10` rows run once (deterministic; `instr` carries the comparison).
- `-N1` rows are the interleaved minimum of 3.
- Driver for the rows this PR adds: [`columnar_wip/bench-om-controls.py`](columnar_wip/bench-om-controls.py), writing [`columnar_wip/om-controls-ab-results.tsv`](columnar_wip/om-controls-ab-results.tsv).
- The tables are built from [`columnar_wip/om-controls-snapshot.tsv`](columnar_wip/om-controls-snapshot.tsv), which [`columnar_wip/combine-om-controls.py`](columnar_wip/combine-om-controls.py) writes, by [`columnar_wip/assemble-hier-gaps.py`](columnar_wip/assemble-hier-gaps.py).

> **This PR pairs every search on the overlapping family with its planted control, and names the om networks in full (F66).**
> - **Before:** the family table had `--regularized` searches with no regularized planted row, and plain planted rows with no plain search next to them.
> - **Now:** it is a grid of 140 rows: 14 networks × {plain, `--regularized`} × {planted, `-2d -N10`, `-2d -N1`, `-d -N10`, `-d -N1`}. Its last column, **Δ vs planted**, compares each search with the planted partition of the same network and objective.
> - **Labels:** om labels name both sizes. `om5_N256_E100k` is the om5 network on N = 256 physical nodes with E = 100 000 trigrams. A bare `om5` meant E100000 for om3–om8 but E50000 for om2.
>
> No engine code and no input changes. The binary is the tip `501f523a`, md5 `54c8b6b21ab1b54dd3931a9c7f79833e`. That is the file #1136 measured: it was built from `c9ce210b`, and nothing under `src/` has changed since.
> - **Carried rows:** every row of #1136's snapshot ([`columnar_wip/inputs-snapshot.tsv`](columnar_wip/inputs-snapshot.tsv)), with its new arm standing for both arms. Each is one measurement, so every carried cell reads (=) and +0.0%. The family's plain search rows are the same runs as the `-C`, `-C -2` and `-C -N1` rows of that network, so the tables agree by construction.
> - **New rows** (old cells "—") are 30 configurations no snapshot had:
>   - 21 planted scores: 14 regularized, plus 7 plain at the density the table lacked;
>   - 7 plain `-2d -N1` at that density;
>   - the two regularized `-N1` rows of om2_N256_E100k, which had `-N10` only.
>
>   Measured 2026-10-12: 3 reps spread across the batch, minimum taken, at load 7–12, so read `instr` before `time`. The session also re-scored the seven plain planted rows the table already had. They give the same bits on all seven, and that run supplies the one-level codelength the last column checks against.
> - **OO arms** are not rerun, since this PR changes nothing the OO engine computes. Their cells are carried as #1136 had them.

### What the change moves

Nothing, in bits or seconds: no carried row has a second measurement. What the PR adds is a planted reference on every family row. Against that reference:

- **Every `-N10` search ends at or below its planted partition except one: om5_N256_E100k `--regularized`, +1.89% in bits.** That is `-2d` at 7.973 bits in 4.81 s and `-d` at 7.973 bits in 4.73 s, against planted 7.826 bits.
  - This is #1042, closed as documented (F61).
  - Seeded from the planted partition (`-c planted`), the same search reaches 7.770 bits, 0.71% below planted. So the objective has a better partition than the free search finds.
  - The snapshot carried this search without its control, so the gap was visible only in `benchmark-networks.md`.
- **`-N1` cells above planted:**
  - **plain `-d -N1`:** om2_N256_E50k +7.62% (0.364 s), om2_N256_E100k +5.34% (0.429 s), om5 +12.80% (0.749 s), om6 +7.82% (0.783 s) and om7 +3.38% (0.800 s), the last three at E100k, all in bits. This is #1121's lone hierarchical trial (F59), closed as documented.
  - **om2_N256_E100k `-d --regularized -N1`:** +7.52% in bits (7.489 bits in 0.468 s, 3 levels, 320 top modules). The `-2d --regularized -N1` partner reaches 6.951 bits, 0.20% below planted. This row is new here, and it is #1121's mode under the regularized objective.
  - **om2_N256_E50k `--regularized -N1`:** +4.77% in bits at both `-2d` and `-d` (7.930 bits in 0.331 s / 0.476 s). It is seed 123's single trial: #1136 found seeds 456, 7, 11 and 99 at 7.532–7.539 bits.
  - **om5_N256_E100k:** plain `-2d -N1` +0.55% (1.62 s); `--regularized -N1` +1.90% (0.706 s / 0.962 s), #1042 as at `-N10`. All in bits.
- **Struck cells:** on nine regularized blocks the planted partition is worse than one-level: om3–om8 at E50k and om6–om8 at E100k. There it is no reference, and the search ends below one-level on all of them.
