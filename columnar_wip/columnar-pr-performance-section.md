## Performance

> Manual old-vs-new benchmark of the `--columnar` engine over the set in [`columnar_wip/benchmark-networks.md`](columnar_wip/benchmark-networks.md). This is **not** the CI `perf-pr.yml` check, which only sees the default OO path since the new core is flag-gated.

Single-threaded (`MODE=release OPENMP=0`), `--seed 123`. Codelength in bits. **`instr` is instructions retired** (`/usr/bin/time -l`). `time` is `--timing-json`'s `timing.total_s`.
- `-N10` rows run once (deterministic; `instr` carries the comparison).
- `-N1` rows are the interleaved minimum of 3.
- Driver: [`columnar_wip/bench-sync.py`](columnar_wip/bench-sync.py) `--carry-oo`, writing [`columnar_wip/hierarchy-roles-ab-results.tsv`](columnar_wip/hierarchy-roles-ab-results.tsv), old and new on every row of the previous snapshot (#1379).
- Bit-identity: [`columnar_wip/bench-identity.py`](columnar_wip/bench-identity.py), every columnar row once per arm, comparing the codelength and the body of every `.tree` file the run writes.
- Outliers in seconds: [`columnar_wip/retime-outliers.py`](columnar_wip/retime-outliers.py), writing [`columnar_wip/hierarchy-roles-retime.tsv`](columnar_wip/hierarchy-roles-retime.tsv).
- Tables: [`columnar_wip/assemble-hier-gaps.py`](columnar_wip/assemble-hier-gaps.py) builds every table from the TSV that [`columnar_wip/tables-1042.py`](columnar_wip/tables-1042.py) `assembly` writes, including the OO cells. The REG table comes from `tables-1042.py reg`.

> **This PR splits the columnar engine into a search class and a hierarchy class (#1371).**
> - `ColumnarTwoLevel` is now the search: the problem (leaf network, flow model, objective corrections), the move loop and the two-level search.
> - `ColumnarHierarchy` (`src/core/ColumnarHierarchy.{h,cpp}`) owns a root search and the `ColumnarStack` from #1379. It holds the operators, the drivers, the dissolve, the scoring and the per-run caches.
> - The move loop becomes a building block: `moveUnits` / `moveLeaves` run it on any level from any seed. The three operators that ran it by setting mode flags by hand now call it.
> - The four member variables that carried one operator's mode into another (`m_externalSeed`, `m_forceHSplit`, `m_refineSweep`, `m_superAggLimit`) are now arguments.
>
> `ColumnarMapEquation.cpp` goes from 2,959 to 1,261 lines, but the move loop's code itself does not move. This is the second step of the split by role Daniel picked for #1371; the finding is F78.
>
> What the snapshot shows:
> - **All 332 columnar configurations are bit-identical**, in codelength and in the body of every `.tree` file a run writes (`_states.tree` included). So are the 33 configurations of [the feature build](#the-feature-build): multilayer input under `--regularized`, and `--lossy`.
> - **Instructions: median −0.02%, 5th–95th percentile −0.74% to +0.06%.** The 267 runs above 1G instructions range from −0.22% to +0.18%. Every row beyond ±1% is a run under 0.14G instructions.
> - **Seconds summed: −0.22%, and the slow cells are noise.** Of the 167 rows above 1 s, the median reads −0.47%, 26 read more than 2% slower and 36 more than 2% faster. The one row more than 10% slower in the sweep, om5_N256_E50k `-d -N10` (+19.4%), reads −0.50% as the minimum of 5. The four rows above 2 s that read more than 5% slower were re-run as the minimum of 10 ([below](#the-slow-cells-are-noise)): −1.87% to +0.16% in seconds, instructions within ±0.01%.
>
> Columnar arms measured in one session, 2026-10-26. OO arms carried from #1379, which carried them from #1378, #1377, #1376, #1373 and #1369's session.
> - **Old:** a fresh build of the branch tip `45fe4995` (#1379), md5 `758547164ea18c4c3f375e3cb9000af4`. It is byte-identical to #1379's new arm. Feature build: md5 `a8c34eb95df5077daaf9f0a8f0b8bf6b`, also identical.
> - **New:** `eb634554`, md5 `66de890a81c3d45a47ebb59c79cf1ae8`. Feature build: md5 `97310f8e908617f0f773b923429914ba`.
> - **Family rows** that repeat a `-C`, `-C -2` or `-C -N1` row take that row's run, so the two tables agree.
> - **This session ran faster than #1379's.** The old arm is the same bytes as #1379's new arm. Over the 167 rows above 1 s it reads median −7.4% in seconds against #1379's snapshot (summed −10.7%), with instructions equal (median −0.04%). The difference is the machine's state, not the code. So every columnar second in the shared tables is lower than in #1379's snapshot, and every gap to the carried OO seconds is wider. The prose under the OO tables quotes the current cells.
