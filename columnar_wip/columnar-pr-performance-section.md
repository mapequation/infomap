## Performance

> Manual old-vs-new benchmark of the `--columnar` engine over the set in [`columnar_wip/benchmark-networks.md`](columnar_wip/benchmark-networks.md). This is **not** the CI `perf-pr.yml` check, which only sees the default OO path since the new core is flag-gated.

Single-threaded (`MODE=release OPENMP=0`), `--seed 123`. Codelength in bits. **`instr` is instructions retired** (`/usr/bin/time -l`). `time` is `--timing-json`'s `timing.total_s`.
- `-N10` rows run once (deterministic; `instr` carries the comparison).
- `-N1` rows are the interleaved minimum of 3.
- Driver: [`columnar_wip/bench-sync.py`](columnar_wip/bench-sync.py) `--carry-oo`, writing [`columnar_wip/pref-comp-ab-results.tsv`](columnar_wip/pref-comp-ab-results.tsv), old and new on every row of the #1408 snapshot.
- Re-timed: the outliers in seconds, with [`columnar_wip/retime-outliers.py`](columnar_wip/retime-outliers.py), writing [`columnar_wip/pref-comp-retime.tsv`](columnar_wip/pref-comp-retime.tsv), as the minimum of 5, interleaved. No codelength changes, so `retime-changed.py` has nothing to run.
- The change itself ([below](#the-24-preferred-modules-runs)): the 24 preferred-modules runs of #1408, [`columnar_wip/pref-comp-vs-1408.tsv`](columnar_wip/pref-comp-vs-1408.tsv), minimum of 3 interleaved, codelengths at full precision; OO from #1408's session, [`columnar_wip/pref-top-vs-oo.tsv`](columnar_wip/pref-top-vs-oo.tsv).
- Tables: [`columnar_wip/assemble-hier-gaps.py`](columnar_wip/assemble-hier-gaps.py) builds every table from the TSV that [`columnar_wip/tables-1042.py`](columnar_wip/tables-1042.py) `assembly` writes, including the OO cells. The REG table comes from `tables-1042.py reg`.

> **This PR lets `--preferred-number-of-modules` merge modules across connected components in the columnar engine (#1407).** The move loop offered a unit only its neighbours' modules, so two components never shared a module, and the bias stopped at the component count, paying a bit for every module above K_pref: netscience (268 components) at K = 50 gave 268 top modules and 222.80 bits under `-2`. OO gets past it through its random moves; with `--num-random-moves 0` it gives the same 222.7997 bits. Now a unit without links at its level, which after aggregation is a whole component, is offered the module of the previous such unit in the shuffled sweep, while the bias still wants fewer modules. There is no random draw and no search, and only a move loop with the bias compiles the candidate in (`moveLoopWith`'s `LinklessPartners`). The finding is F85.
>
> What the snapshot shows:
> - **On the 24 preferred-modules runs, 5 change** ([below](#the-24-preferred-modules-runs)). netscience K = 50 reaches 50 top modules: `-2` 222.80 → 5.137 bits (OO 4.799), standard 221.36 → 3.365 bits (OO 3.404), at +0.001 s and +0.003 s. science2001 K = 25 `-2` −0.19% in bits; air30k K = 20 `-2` −0.87%, standard **+0.076%**. The other 19 are identical at full precision.
> - **No configuration of the snapshot changes codelength:** none combines the bias with a network that has more than one component.
> - **Nothing else pays for it:** instructions +0.019% summed over the 332 configurations, median −0.004% over the 295 above 0.3G (5th–95th percentile −0.16% to +0.13%). Seconds +0.32% summed; the 9 outliers re-time to −4.9% to +6.2% at −0.13% to +0.06% in instructions.
> - **Worse cells:** air30k's standard search (+0.076% in bits) and netscience `-2` against OO (+7.04% in bits), [explained below](#every-cell-that-is-worse-explained).
>
> Columnar arms measured in one session, 2026-11-05, interleaved per row, with no other benchmark or test suite running.
> - **Old:** #1408's head `61f8b9d8`, the base of this stacked PR, md5 `406af3129e00a2545879de5cb3ae7bd2`. Once #1408 lands, the tip of `columnar-hierarchical-core` builds to this binary.
> - **New:** `2902710e`, md5 `4ade69dbb25c7479ae8819c8e5889295`.
> - **OO arms** are carried from #1408's TSV: this PR changes only columnar code.
> - **The feature build** is not re-run: none of its configurations sets `--preferred-number-of-modules`, so they all run the move loop without the candidate, which is the code they ran before. Its tests pass (below).

#### The candidate's loop, and what it cost before

The first cut put the candidate in the move loop every run uses. It changed no codelength, but the sweep read +0.24% in instructions summed (median +0.21%) on runs that never offer it. Checking the units once per sweep instead of once per visit did not help, so the loop is now compiled twice, and only a loop with a correction that steers the number of modules (`targetTopModules`) carries the candidate. Instructions retired against #1408, minimum of 3 ([`columnar_wip/pref-comp-loop-variant.tsv`](columnar_wip/pref-comp-loop-variant.tsv); `pc` is the first cut, `pc2` this PR):

#### Every cell that is worse, explained

- **In bits, against #1408:** air30k K = 20 standard, 5.416326 → 5.420466 (+0.076%), at −0.1% in seconds. Its 6 small components become units without links, and the candidate changes the trajectory; the same run under `-2` is −0.87%.
- **In bits, against OO:**
  - netscience K = 50 `-2`, 5.137 against 4.799 (+7.04%), from 222.80 before this PR. The two engines spend the merges differently. OO keeps the 379-node component in 15 modules and groups the small components into about 35 modules of up to 20; this PR squeezes it into 5 modules and spreads the small components over 45 of up to 8. A merge inside the large component costs more bits than a merge between small components. The bias prices every merge the same, so the order the search offers them decides: the move loop takes the large component's merges in every sweep, while the pairing can halve the units without links only once per aggregation pass.
  - Unchanged from #1408: word_assoc K = 3000 +0.80%, polblogs K = 5 `-2` +0.12%. science2001 `-2` drops from +0.22% to +0.03%.
- **In seconds, on changed runs:** netscience +11.3% (`-2`, 0.013 → 0.014 s) and +10.6% (standard, 0.032 → 0.035 s): the 218 merges the bias now makes. science2001 `-2` +0.9%.
- **In seconds, on the snapshot's bit-identical rows:** none after re-timing beyond noise. The 9 outliers (+10% to +18% in the sweep) re-time to −4.9% to +6.2% at −0.13% to +0.06% in instructions. The largest, om4_N256_E50k `-C -2d -N10` at +6.2%, retires 0.04% fewer instructions than #1408: the same work, so the seconds are timing.

  search is worse.

  planted partition is worse than one-level: it is no reference, and the block's deltas are ~~struck~~.
- The plain search rows are the same runs as the `-C`, `-C -2` and `-C -N1` rows of that network.
- Every row is bit-identical: no family run sets a preferred number of modules.

### OO vs columnar

OO cells are carried from #1398's session, which measured them alongside that PR's columnar cells; this PR
changes no OO code. air30k (meta)'s come from the #1168 session, since the sweep does not run it (#1134). The
seconds gaps therefore mix two sessions; the instruction gaps do not. One row changes in bits, on the columnar
side: **word_assoc (pref.) goes from 0.152% below OO to 1.89% below it**, and from −21.2% in instructions to
+13.6%. Both engines now charge the top modules (#1068), and this PR's top there is padded: one module holds
nearly everything (1.0 effective top modules, OO 21.4). Columnar ends more than 0.1% above OO in bits on no row of
this table.

wikispeedia `-d` is 0.077% below OO in bits at −48% in instructions, although columnar still returns two
levels where OO finds three (#1157). air30k (reg.) is −0.135% in bits at −32% in instructions, web-NotreDame
+0.054% at −87%, and malaria −1.69% at −51%.

**air30k (meta) is not a comparison.** OO finishes it (#1134, closed by #1142), but on metadata over
higher-order input the engines deliberately optimize different objectives (F39, #1012). The columnar
engine adds the metadata term to the full higher-order objective; OO scores state nodes only, without
the physical-node codebook. Scoring each engine's `-2` partition under the other engine confirms it:
columnar's prices at 7.416 bits under `-C` and 11.092 under OO, and OO's at 9.119 and 9.225. Without
`--meta-data` the two engines agree on both partitions to every printed digit. So the row shows no delta,
and earlier snapshots' "−12% against OO" on this row (#1077) compared two objectives.
